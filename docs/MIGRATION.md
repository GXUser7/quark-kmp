# Перенос quark на Kotlin Multiplatform

Документ описывает, что представляет собой исходный проект, во что он переносится и в каком
порядке. Все утверждения об оригинале проверены по коду в `E:\Projects\quark` (коммит `bd61c35`).

## 1. Что переносим

quark — десктопный аудиоплеер на Flutter: ~32,6 тыс. строк Dart в `lib/` (из них 3,9 тыс. —
сгенерированный Drift) плюс 5,1 тыс. строк в двух вендоренных библиотеках
(`lib/overrided_libraries/yandex_music` и `animated_expand`). Таргеты — только десктоп:
папки `windows/`, `linux/`, `macos/` есть, `android/` и `ios/` нет, хотя виджет
`android_player.dart` в коде присутствует.

Функционально это: локальная библиотека с чтением тегов, интеграция с Яндекс.Музыкой
(включая «Мою волну» и синхронизированные тексты), YouTube Music через собственный
бэкенд `quarkaudio.ru`, статистика прослушиваний, системные медиа-контролы, Discord RPC
и локальное HTTP/WebSocket API для внешнего управления.

## 2. Цель

Compose Multiplatform на JVM 21, Windows / Linux / macOS. Kotlin 2.3.10, Compose 1.11.1,
Gradle 9.7 — те же версии, что в YumiDesktop, чтобы тулчейн и кэш Gradle переиспользовались.

KMP-плагин используется даже при одном таргете `jvm()`: бизнес-логика лежит в `commonMain`,
платформенное — за `expect`/`actual`. Добавить Android или iOS потом можно будет без
перекладывания кода.

## 4. Что уже сделано

Подробный план работ — в [PLAN.md](PLAN.md), решение по движку — в
[decisions/01-audio-engine.md](decisions/01-audio-engine.md).

**Этап 1, инфраструктура — закрыт.**
* Шесть Gradle-модулей, сборка проходит, 44 теста зелёные.
* `Settings` — одна модель вместо 38 `ValueNotifier`, пишется атомарно в json;
  битый файл откладывается в `.broken`, а не молча заменяется дефолтами.
* `DatabaseFactory` открывает существующий `quark.db` от Drift без миграции.
* Репозитории треков, плейлистов и статистики поверх SQLDelight, 10 тестов.

**Этап 2, аудио-движок — код написан, не проверен вживую.**
* JNA-биндинг клиентского API mpv, событийный цикл на своём потоке.
* `MpvAudioEngine`: gapless через `loadfile append`, естественный переход
  распознаётся по росту `playlist-pos`; заголовки запросов выставляются
  перед каждой загрузкой.
* `PlayerController` разведён на два пути: ручное переключение открывает трек,
  а естественное — только догоняет состояние, потому что mpv уже играет.
* 8 тестов на контроллер поверх записывающего двойника движка.
* **Нужен `libmpv`**: на машине разработки его нет, звук не проверен.

**Этап 3, локальная библиотека — частично.**
* `TagReader` на jaudiotagger: теги, встроенная обложка, обложка рядом с файлом.
* `LibraryScanner`: обход папок, параллельное чтение тегов, прогресс.
* Осталось: CUE, слежение за папками, запись тегов.

**Этап 4, Яндекс.Музыка — основное готово.**
* `YandexClient` на Ktor: два набора заголовков, разбор ошибок в типы.
* Аккаунт, плейлисты, треки, альбомы, артисты, поиск, ссылка на файл,
  тексты, «Моя волна» с фидбеком.
* Подписи покрыты тестами против эталонов, посчитанных независимо.
* Путь кеша `cisum_xednay_krauq<id>.flac` сохранён — файлы, скачанные
  Flutter-версией, подхватятся.
* 11 тестов на Ktor MockEngine.

**Этап 8, плеер — первая версия.**
* `PlayerViewModel` — один state holder вместо четырёх копий логики.
* Три раскладки по размеру окна, пороги те же, что в `playlist_page_router.dart`.
* Обложки: декодирование через Skia, LRU-кеш, извлечение акцентных цветов
  портом `AccentColorService`.
* Диалоги файлов и папок вместо `file_picker`.

## 6. Риски, по убыванию

1. **Аудио-движок.** В JVM нет встроенного бэкенда, который тянет FLAC/ALAC/Opus, gapless,
   сетевые потоки и смену темпа без сдвига тона. Нужна нативная библиотека (`libmpv` —
   ближайший аналог `media_kit`, либо `libvlc` через VLCJ), и её бинарники придётся класть
   в дистрибутив. Оригинал не случайно держит переключатель трёх бэкендов: ни один не
   закрывал все случаи.
2. **Клиент Яндекс.Музыки.** Неофициальное API: подписи, ротор, ссылки на файл через XML.
   Логика в оригинале размазана по архитектуре Dio — переписывать, а не портировать.
   Протокол задокументирован в отчётах анализа; подписи уже перенесены и покрыты тестами.
3. **Системные медиа-контролы.** SMTC на Windows в оригинале работает через Rust-мост;
   на JVM это JNA/Panama поверх WinRT. MPRIS на Linux — `dbus-java`.
4. **Шейдер `vibe.frag`.** 208 строк GLSL с симплекс-шумом. В SkSL переписывается механически
   (`FlutterFragCoord()` → аргумент `main`, `out vec4 fragColor` → возврат `half4`), но
   массивы `vec3[6]` и `vec3[3]` придётся разворачивать в плоский буфер униформ.
5. **Вход в Яндекс.** WebView2 на десктопе в JVM тянет за собой JCEF (+100 МБ). Разумнее
   системный браузер и перехват токена локальным сервером; ручной ввод токена в оригинале
   уже есть как запасной путь.

## 7. Что нельзя портировать построчно

* `widgets/players_widgets/*.dart` (main 1626 + android 1234 + mini 501 + macro 730 строк) —
  один и тот же плеер, скопированный четыре раза вместе с логикой, подписками и
  форматированием времени. В Compose это один state holder и несколько раскладок.
* `widgets/yandex_music_integration/yandex_widgets.dart` (2232 строки) — 14 разнородных
  классов в одном файле, включая экран артиста, дублирующий `media_cards/artist.dart`.
* `services/database/database.dart` — 38 `ValueNotifier` с ручным сохранением каждого.
  Заменяется одной моделью настроек, сохраняемой целиком.
* Связка Hive + Drift — две базы там, где хватает одной плюс файл настроек.

## 8. Дефекты оригинала, которые не надо переносить

Найдены при разборе; в порте либо уже исправлены, либо помечены.

* `PlayerTrack` и наследники не переопределяют `==` и `hashCode`, поэтому трек, пересозданный
  из БД, не равен себе же в плейлисте, и `indexOf` молча возвращает -1.
  *В порте: `Track` — `data class`, сравнение по значению; есть тест.*
* `serializePlaylist` (`objects/playlist.dart:38`) молча выбрасывает `YTMusicTrack` и
  `ShowTrack` — они не сохраняются в плейлист. Там же при десериализации источник
  `youtube` не разбирается и откатывается в `local`.
* `_getNext` (`player.dart:562`) при включённом repeat и треке из очереди, которого нет в
  плейлисте, обращается к `playlist[-1]`. *В порте возвращается `null`.*
* `main.dart:39-45` — инициализация БД обёрнута в `catch (e) {}`, ошибка диска проходит молча.
* `CoverType.parseString` сравнивает с `"buildIn"`, тогда как сериализуется `"builtIn"`;
  совпадает только потому, что `default` возвращает то же значение.
* Мёртвый код: `Player.queue2`, весь `objects/cover.dart`, зависимости `provider`,
  `marquee`, `palette_generator`.
